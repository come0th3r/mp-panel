# Единый Minecraft-шлюз

Панель поддерживает mc-router и Gate Lite. Оба маршрутизируют Minecraft Java соединения по hostname из игрового handshake: разные домены ведут на один публичный IP:25565, а внутри сети соединения передаются на разные адреса и порты.

HTTP Proxy Host в Nginx Proxy Manager маршрутизирует веб-приложение панели. Для игровых доменов нужен Minecraft-aware шлюз. NPM TCP Stream может прозрачно передавать TCP шлюзу, но самостоятельно не выбирает backend по Minecraft hostname.

## mc-router

Используется [официальный релиз v1.47.2](https://github.com/itzg/mc-router/releases/tag/v1.47.2), образ закреплён OCI digest. В `.env` включите:

```dotenv
MP_ENABLE_GATEWAY=true
MP_GATEWAY_PROVIDER=mc-router
MP_GAME_DOMAIN=mc.example.com
MP_GATEWAY_BIND=0.0.0.0
MP_GATEWAY_PORT=25565
```

SSH-установщик выберет overlay автоматически. Для ручного запуска:

```sh
docker compose -f compose.yaml -f deploy/compose.mc-router.yaml up -d --build --wait
```

Порт шлюза не должен совпадать с портом другого сервиса на том же адресе. Если Minecraft на этой машине уже занимает 25565, задайте `MP_GATEWAY_PORT=25566`. На сетевом роутере направьте внешний TCP 25565 на адрес машины со шлюзом и выбранный внутренний порт. A-запись игрового домена и wildcard-запись его поддоменов должны указывать на публичный адрес шлюза. Например, для `MP_GAME_DOMAIN=mc.example.com` нужны записи `mc.example.com` и `*.mc.example.com`. Замените пример своим доменом. Панель не изменяет DNS и NAT автоматически.

Управляемому серверу домен назначается во вкладке «Сеть». Для уже установленных сторонних серверов откройте «Настройки → Игровые домены»: нужны название, домен и IP:порт, доступный шлюзу. SSH, агент и переустановка для такого маршрута не нужны. Он предоставляет игровой адрес; управление файлами, ядром и запуском остаётся в существующей системе.

REST API mc-router доступен только внутри сети Compose: `http://mc-router:8080`, без публикации административного порта. Панель использует GET/POST/DELETE `/routes` и сверяет маршруты каждые 15 секунд. PostgreSQL хранит желаемое состояние, а volume `mc-router-config` хранит конфигурацию роутера. Точный чужой маршрут с новым доменом не перезаписывается. Статус «Правило применено» подтверждает настройку, но не сетевую доступность backend или публичного входа. [Upstream API](https://github.com/itzg/mc-router#rest-api).

До изменения маршрутов панель фиксирует владение проверенными доменами в БД. История владения сохраняется и после удаления: это позволяет удалить устаревшую запись, если upstream не сохранил удаление на диск и восстановил её после перезапуска. Ограничения: 2000 текущих маршрутов, 4000 закреплённых доменов с учётом истории. Изменять маршруты через административный API должна только панель.

Upstream записывает JSON-файл неатомарно и сообщает об ошибках сохранения только в логах. При повреждении файла роутер может не запуститься: сохраните повреждённый файл для диагностики, восстановите корректный JSON `{"mappings":{}}` с владельцем UID/GID 65532 и перезапустите роутер; панель восстановит актуальные маршруты из БД. Volume и БД должны входить в резервное копирование. [Исходник сохранения](https://github.com/itzg/mc-router/blob/v1.47.2/server/routes_config_loader.go).

## Gate Lite

[Официальное описание Gate Lite](https://gate.minekube.com/guide/lite). Этот адаптер остаётся альтернативой mc-router; включайте только один gateway overlay.

### Установка

Используется официальный релиз [Gate v0.74.27](https://github.com/minekube/gate/releases/tag/v0.74.27), закреплённый также SHA-256 digest образа. В этом релизе исходники подтверждают методы GetConfig / ApplyConfig, версионирование и обновление Java Lite маршрутов без перезапуска. [API](https://gate.minekube.com/developers/api/), [OpenAPI и JSON поля](https://gate.minekube.com/developers/api/openapi), [исходный handler релиза](https://github.com/minekube/gate/blob/v0.74.27/pkg/gate/api_handlers.go).

Добавьте в `.env`:

```dotenv
MP_ENABLE_GATEWAY=true
MP_GATEWAY_PROVIDER=gate
MP_GAME_DOMAIN=mc.example.com
MP_GATEWAY_BIND=0.0.0.0
MP_GATEWAY_PORT=25565
```

Установщик включит соответствующий Compose overlay. Когда игровой хост и шлюз находятся на одной машине, назначайте backend-серверам другие порты, например 25566 и 25567, чтобы не конфликтовать с портом 25565 шлюза.

Для ручного запуска добавьте overlay к основной конфигурации:

```sh
docker compose -f compose.yaml -f deploy/compose.gate.yaml up -d --build --wait
```

Если веб-панель использует общий Docker-network с NPM:

```sh
docker compose -f compose.yaml -f deploy/compose.npm.yaml -f deploy/compose.gate.yaml up -d --build --wait
```

Gate публикует только игровой TCP 25565. Его административный API 8080 доступен исключительно в приватной сети Docker по адресу `http://gate:8080`; в интернет он не публикуется. У самого Gate API нет встроенной авторизации, поэтому не открывайте этот порт или NPM Proxy Host к нему. При вынесении Gate на другой хост обеспечьте защищённую приватную сеть и дополнительное ограничение доступа к API.

Первый запуск копирует seed-конфигурацию в volume `mp-panel_gate-config`. После этого Gate сохраняет изменения в этом volume; повторный запуск не перезаписывает актуальные маршруты исходным seed-файлом. Образ работает с config-файлом в writable volume: readonly bind mount сделал бы `persist:true` невозможным.

## Маршруты и владение

Панель хранит явные домены и backend-адреса вида `10.20.0.15:25566`. Gateway adapter получает существующий YAML, сохраняет посторонние маршруты и все их параметры, удаляет только точные hostname, которые панель ранее зарегистрировала, и добавляет актуальные записи MP. Совпадение нового домена с существующим посторонним маршрутом отклоняется. Wildcard для маршрутов панели запрещён.

При сохранении adapter отправляет только JSON Merge Patch для `config.lite.routes`, с текущим `ifMatch` и `persist:true`. Конкурентное изменение требует повторного получения версии. Неизменившиеся маршруты не записываются повторно.

Если Gate сообщает, что изменение применено в памяти, но запись на диск не удалась, панель сохраняет владение доменами, показывает ошибку и повторяет сохранение. Признак незавершённого сохранения хранится в БД и восстанавливается после перезапуска API. При потере HTTP-подтверждения adapter ограниченно перечитывает конфигурацию: подтвердить применение можно только при изменившейся версии и полном совпадении маршрутов с ожидаемыми. До успешного сохранения предупреждение остаётся видимым.

Gate требует хотя бы один маршрут в Lite-конфигурации. Пока реальных маршрутов нет, сохраняется инертная запись `mp-disabled.invalid → 127.0.0.1:1`. Она не является default/wildcard backend и не открывает доступ к Minecraft.

Управляемые точные маршруты стоят перед сохранёнными внешними wildcard-маршрутами. DNS записей adapter не создаёт: назначьте A/AAAA соответствующих поддоменов на IP шлюза, либо заранее подготовьте wildcard DNS в своей зоне. Все управляющие операции должны выполняться через авторизованную API панели, не напрямую из браузера в Gate.

## Приватные игровые хосты

Gate должен видеть backend-адреса по маршрутизируемой сети. Для удаления публичного доступа к игровым портам сначала подготовьте WireGuard или другую приватную сеть между шлюзом и игровыми хостами, затем задайте адрес VPN в поле «Адрес игровых портов» при подключении каждого хоста и ограничьте входящие соединения firewall. SSH-адрес хоста может отличаться от игрового backend; задавайте фактический адрес VPN в маршруте.

Сам adapter не создаёт VPN и не меняет firewall. Он сохраняет Minecraft hostname и передаёт player authentication backend-серверу: `online-mode` сервера сохраняет свой смысл. PROXY protocol не включается автоматически, поскольку Vanilla и некоторые загрузчики его не понимают. [Gate Lite forwarding](https://gate.minekube.com/guide/lite).
