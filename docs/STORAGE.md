# Хранение и очистка

Панель хранит данные в нескольких местах. Размер `/var/lib/docker` включает данные приложений, образы и кэш сборок; это не размер одного исполняемого файла панели.

| Данные | Где хранятся | Что сохранять |
|---|---|---|
| Учётные записи, серверы, задания | Docker volume `mp-panel_database` | Вся база PostgreSQL |
| Ключ шифрования и CA | `keys` в volume `mp-panel_panel-data` | Все ключи, без них нарушается доступ к секретам и агентам |
| Исходные копии загрузок | `uploads` в том же volume | Пока агент не завершил передачу |
| Копии для отката обновления | `/var/lib/mp-panel-updates/<Compose-проект>` | Последняя успешная копия, по умолчанию одна |
| Миры, моды, плагины и игровые копии | `/var/lib/mp-agent` на игровом хосте | Данные серверов, независимо от панели |
| Образы и кэш сборок | Хранилище Docker | Работающие образы; кэш можно восстановить новой сборкой |

## Автоматическая уборка

Начиная с v0.4.2 API раз в минуту проверяет до 500 старых загрузок. После успешной передачи исходная копия удаляется не раньше чем через 10 минут после завершения задания. Неиспользованные и неудавшиеся загрузки хранятся минимум сутки. После истечения срока задания копия сохраняется ещё сутки. Ссылки из любых незавершённых команд запрещают удаление.

Уборка удаляет только копию на панели и её запись загрузки. Файлы на игровом хосте, учётные записи, настройки и ключи сохраняются. Для повторной установки собственного JAR или повторной отправки удалённой копии выберите файл заново. Очередь команд и уборка используют блокировки базы, чтобы уборка не могла удалить файл, который только что назначили агенту.

После успешного обновления установщик оставляет последнюю копию для отката и удаляет более ранние завершённые копии. Если новое обновление не удалось, его уборка не запускается. Незавершённые попытки восстановления сохраняются для разбора. Настройка в `/opt/mp-panel/.env` позволяет оставить больше успешных копий:

```dotenv
MP_UPDATE_BACKUPS=2
```

Допустимы значения от 1 до 100, по умолчанию 1. Копия содержит весь том panel-data, поэтому обновление во время хранения большого мира в загрузках может временно требовать столько же места для архива. Установщик не исключает загрузки из согласованной копии: иначе откат восстановил бы базу со ссылками на отсутствующие файлы.

После успешного обновления установщик также очищает неиспользуемый общий кэш сборок Docker с целевым остатком 1 ГБ. Это не жёсткий предел всего хранилища: используемый кэш и слои, общие с сохранёнными образами, могут остаться, поэтому `docker system df` может показывать больше 1 ГБ. Это не удаление Docker-томов и не очистка образов игровых серверов. Если на машине собираются другие проекты, их будущие сборки тоже могут заново скачать зависимости. Чтобы сохранить кэш, добавьте:

```dotenv
MP_PRUNE_BUILD_CACHE=false
```

## Очистка старой панели до обновления

В версиях до v0.4.2 исходные копии загрузок не удалялись автоматически. Несколько отправок одного мира могли занять десятки гигабайт и затем попасть в резервную копию обновления.

На машине с панелью нужен Python 3, Docker и root/sudo. Сначала скачайте утилиту и контрольные суммы из одного релиза:

```bash
mkdir -p /root/mp-storage-cleanup
cd /root/mp-storage-cleanup
curl -fL https://github.com/come0th3r/mp-panel/releases/download/v0.4.2/cleanup-storage.py -o cleanup-storage.py
curl -fL https://github.com/come0th3r/mp-panel/releases/download/v0.4.2/SHA256SUMS -o SHA256SUMS
awk '$2 == "cleanup-storage.py" {print}' SHA256SUMS > cleanup.sha256
test -s cleanup.sha256 && sha256sum -c cleanup.sha256
```

Посмотрите объём кандидатов, не удаляя файлы:

```bash
sudo python3 cleanup-storage.py --directory /opt/mp-panel
```

Если старые копии больше не нужны, выполните очистку:

```bash
sudo python3 cleanup-storage.py --directory /opt/mp-panel --apply
```

Утилита кратковременно останавливает только API и worker, повторно проверяет отсутствие незавершённых заданий и удаляет копии старше суток. Затем запускает те же контейнеры, которые работали до очистки. Для нестандартного Compose-проекта укажите `--project ИМЯ`. Установка проверяется по меткам контейнеров; секреты из `.env` не выводятся.

Копии неудавшихся загрузок тоже удаляются: для повторной отправки потребуется снова выбрать исходные файлы. Обычные файлы без записи загрузки удаляются только из каталога uploads, если имя соответствует идентификатору панели, нет ссылок и файл старше суток. Свежие и неизвестные файлы остаются. Ключи, миры, база пользователей и архивы обновлений сохраняются.

После очистки запустите установщик нового релиза. Не используйте удаление всего `panel-data` или `docker compose down -v`: они затрагивают необходимые данные.

## Проверка места

Выполняйте команды по отдельности:

```bash
cd /opt/mp-panel
docker compose exec -T api du -h -d 1 /var/lib/mp
docker system df -v
sudo du -h -d 2 /var/lib/mp-panel-updates
df -h /
```

Если резервная копия всё ещё большая, очистка uploads её не уменьшает: это отдельный архив. После следующего успешного обновления лимит копий удалит прежние завершённые архивы. Не удаляйте единственную копию, которая нужна для отката.
