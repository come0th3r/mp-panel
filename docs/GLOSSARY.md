# Термины MP Panel

Краткий словарь помогает разобраться в панели, подключении игровых хостов и настройке Minecraft-серверов.

## Панель и подключение

**Панель** — веб-приложение, в котором администратор подключает игровые хосты, создаёт серверы и управляет ими.

**Игровой хост** — Linux-машина, подключённая к панели. Обычно в интерфейсе она называется «Хост». На ней находятся агент и файлы игровых серверов. Один хост может запускать несколько серверов.

**Агент** — программа на игровом хосте. Она получает команды панели по защищённому соединению, управляет контейнерами и файлами, а также передаёт состояние и метрики.

**SSH** — защищённый способ подключения к Linux-машине. Панель использует его при первоначальном подключении хоста и обновлении агента.

**Отпечаток ключа хоста (fingerprint)** — короткое представление SSH-ключа машины. Его сверяют перед подключением, чтобы убедиться, что SSH ведёт к нужному хосту.

**mTLS** — проверка подлинности обеих сторон TLS-соединения: панель проверяет сертификат агента, а агент — сертификат панели.

**Docker** — программа для запуска изолированных контейнеров. Панель запускает каждый игровой сервер в отдельном контейнере.

**Контейнер** — запущенный экземпляр программы с отдельным окружением. Файлы мира и настройки Minecraft хранятся на хосте, чтобы пережить пересоздание контейнера.

**Образ Docker** — шаблон, из которого создают контейнер. Например, образ с нужной версией Java используется для запуска игрового сервера.

**Compose** — конфигурация связанных контейнеров панели. Она описывает API, обработчик заданий, базу данных и, при включении, игровой шлюз.

**`.env`** — локальный файл настроек установки. В нём находятся адреса панели и другие значения, нужные Compose. Файл содержит секреты и не должен публиковаться.

## Игровые серверы и файлы

**Игровой сервер** — созданный в панели экземпляр Minecraft. У него есть имя, версия, выбранное ядро, настройки запуска и каталог с игровыми файлами.

**Ядро (core)** — серверная программа Minecraft. В панели доступны, среди прочего, Vanilla, Paper, Spigot, Fabric, Forge и NeoForge. Возможности модов и плагинов зависят от выбранного ядра.

**Загрузчик модов (loader)** — компонент, который подключает моды к Minecraft. Fabric, Forge и NeoForge — примеры загрузчиков; это не отдельные версии самой игры.

**Версия Minecraft** — версия игры, с которой должен быть совместим сервер, например 1.21. Ядро, моды и клиенты игроков должны поддерживать совместимые версии.

**Сборка (build)** — конкретный выпуск ядра для выбранной версии Minecraft. У одного ядра и версии игры может быть несколько сборок.

**Java** — среда выполнения серверной программы Minecraft. Панель подбирает её версию по профилю установки.

**JAR** — файл Java-программы. Серверный JAR запускает Minecraft; моды и некоторые плагины также распространяются в JAR-файлах.

**Мод** — расширение игры, обычно работающее и на сервере, и у игрока. Для запуска требуются совместимые ядро, версия Minecraft и, иногда, загрузчик на клиенте.

**Плагин** — расширение серверной программы, чаще всего предназначенное для Paper или Spigot. Обычно игроку не нужно отдельно устанавливать такой плагин.

**`server.properties`** — основной текстовый файл настроек Minecraft: например, имя мира, режим игры, порт и правила подключения.

**Корень сервера** — верхний каталог файлов одного игрового сервера в файловом менеджере. Загруженные пути считаются относительно этого каталога.

**Каталог версий** — доступные панели профили установок, полученные из внешних источников и сохранённого списка. Обновление каталога показывает новые варианты, но не меняет уже установленные серверы.

**Артефакт** — файл, подготовленный для установки или загрузки, вместе с его именем, размером и контрольной суммой. Панель передаёт его агенту, чтобы тот проверил файл перед сохранением.

**EULA Minecraft** — лицензионные условия Minecraft. При создании сервера пользователь должен сам подтвердить согласие с ними в панели.

**Резервная копия** — архив файлов игрового сервера, который панель создаёт на игровом хосте. Её можно восстановить через панель. Для защиты при поломке самого хоста нужна отдельная копия за его пределами.

## Задания и состояние

**Задание (job)** — операция, которую панель поставила в очередь: например, установка сервера, загрузка файлов или создание резервной копии. На странице задания видны этапы и результат.

**Статус задания** — состояние операции: `queued` означает ожидание, `running` — выполнение, `succeeded` — успех, `failed` — ошибку.

**Статус сервера** — последнее известное панели состояние игрового контейнера, например «Работает», «Остановлен» или «Ошибка». Если агент давно не связывался с панелью, показанные метрики могут быть устаревшими.

**Желаемое состояние** — состояние, которое запросили в панели: например, запущен или остановлен. Во время запуска оно может временно отличаться от последнего наблюдаемого статуса.

**CPU** — доля вычислительной мощности процессора, которую использует сервер.

**RAM** — оперативная память, занятая контейнером игрового сервера.

**I/O** — чтение с диска и запись на диск. Панель показывает накопленные счётчики этих операций.

## Учётные записи и безопасность

**Владелец (owner)** — учётная запись, созданная при первой настройке панели. Владелец управляет пользователями, хостами и настройками панели.

**Администратор (admin)** — пользователь с правами управлять игровыми серверами и основными операциями панели. Часть настроек владельца ему недоступна.

**Оператор (operator)** — пользователь, которому владелец назначил конкретные игровые серверы. Оператор может полностью управлять назначенными серверами, включая файлы и смену ядра.

**Наблюдатель (viewer)** — пользователь, который может просматривать доступные сведения, но не управлять серверами.

**2FA / TOTP** — вход с одноразовым кодом из приложения-аутентификатора. Код меняется через короткие промежутки времени.

**Код восстановления** — одноразовый запасной код для входа, если приложение-аутентификатор недоступно. Сохраните его отдельно и не отправляйте другим людям.

**Аудит** — журнал важных действий в панели с пользователем, временем и объектом операции.

## Домены и маршрутизация

**Игровой порт** — TCP-порт, на котором сервер принимает соединения Minecraft. Панель и игровой шлюз могут использовать разные порты.

**DNS** — система, которая связывает доменное имя с IP-адресом. Панель не изменяет DNS-записи автоматически.

**Игровой маршрут (route)** — правило, связывающее Minecraft-домен с адресом и портом игрового сервера.

**Backend маршрута** — внутренний IP-адрес и порт, куда шлюз передаёт соединение игроков.

**mc-router и Gate Lite** — игровые шлюзы, которые читают имя хоста из соединения Minecraft и выбирают соответствующий backend. Это нужно, чтобы направлять несколько доменов через один публичный порт.

**Внешний маршрут** — запись для уже существующего сервера, который не подключён к панели как игровой хост. Она настраивает только адрес через шлюз; запуском, файлами и ядром этого сервера панель не управляет.

**Nginx Proxy Manager (NPM)** — веб-интерфейс настройки Nginx. Он может проксировать веб-панель и передавать Minecraft TCP-трафик игровому шлюзу, но HTTP-прокси NPM сам по себе не выбирает игровой сервер по Minecraft-домену.

## Обновление

**Установщик** — скрипт `setup.sh` или `setup.ps1`, который устанавливает панель или обновляет её на сервере.

**Откат обновления** — восстановление прежней версии панели, если новая версия не запустилась. Установщик сохраняет резервные данные обновления; отдельные копии игровых миров создаются независимо.
